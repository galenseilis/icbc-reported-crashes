# Dataset schema

This page describes the CSV produced by `export_dashboard_data.py` and the fields
that feed it. The canonical machine-readable version is
`data/processed/icbc_reported_crashes.schema.json`, generated by the export.

The examples and counts below are from the documented 2021–2025 snapshot:
1,453,136 records, 27 columns. The export includes all discovered physical columns,
so a future source with extra columns can produce a wider CSV. See
[Schema evolution](metadata-files.md#schema-evolution).

## Grain

A **record** is one distinct combination of the non-measure dimensions. The two
measures are `TOTAL_CRASHES` and `TOTAL_VICTIMS`; the derived `(ifnull)` fields are
functions of other columns. On the documented snapshot, the 23 non-measure,
non-derived columns uniquely identify every row.

This means:

- `COUNT(*)` (or `len(df)`) is the number of **records**, not crashes.
- `SUM(TOTAL_CRASHES)` is the number of **crashes** (1,465,435).
- `SUM(TOTAL_VICTIMS)` is the number of **victims** (347,413).

Most records represent one crash. In this snapshot, 1,441,897 records have
`TOTAL_CRASHES = 1`; 11,239 records represent two or more crashes. The maximum is
11. See [Rows are not crashes](../explanation/data-limitations.md#rows-are-not-crashes).

A record is not an individual crash, vehicle, person, or claim. It has no unique
crash identifier, and it does not contain an exact date (only year, month,
weekday, and a three-hour time bucket).

`CSV type` is the type of the physical Hyper column where one exists. The CSV
itself is untyped text; consumers must parse the integer and floating-point
columns.

## Columns by role

### Time and place

| Column | Role |
|---|---|
| `DATE_OF_LOSS_YEAR` | Year of crash |
| `MONTH_OF_YEAR` | Month name |
| `DAY_OF_WEEK` | Weekday name |
| `TIME_CATEGORY` | Three-hour bucket |
| `LATITUDE`, `LONGITUDE` | Approximate coordinates |
| `REGION` | ICBC region |
| `MUNICIPALITY_NAME` | Municipality from claim reports |
| `MUNICIPALITY_WITH_BOUNDARY` | Municipality including border municipalities |
| `STREET_FULL_NAME` | Street or road infrastructure |
| `CROSS_STREET_FULL_NAME` | Cross street at an intersection |
| `ROAD_LOCATION_DESCRIPTION` | Free-text location description |

There is no day-of-month or full date field. A year/month/weekday/time bucket can
correspond to several actual dates, so the data cannot support exact-date
analysis.

### Crash characteristics

| Column | Role |
|---|---|
| `CRASH_SEVERITY` | Casualty versus property damage only |
| `DERIVED_CRASH_CONFIGURATION` | Claim-derived configuration |
| `INTERSECTION_CRASH` | Intersection indicator |
| `MID_BLOCK_CRASH` | Mid-block indicator |
| `PARKING_LOT_FLAG` | Parking-lot indicator |
| `ROAD_LOCATION_DESCRIPTION` | Location narrative |

### Involvement flags

All flags use `Y`/`N` with no nulls in this snapshot:

| Column | `Y` means |
|---|---|
| `ANIMAL_FLAG` | An animal was involved |
| `CYCLIST_FLAG` | At least one cyclist was involved |
| `HEAVY_VEH_FLAG` | A heavy vehicle (gross vehicle weight over 10,900 kg) was involved |
| `MOTORCYCLE_FLAG` | A motorcycle, moped, scooter, or trike was involved |
| `PARKED_VEHICLE_FLAG` | At least one involved vehicle was parked |
| `PEDESTRIAN_FLAG` | At least one pedestrian was involved |

### Measures

| Column | Meaning | Snapshot range | Snapshot sum |
|---|---|---|---|
| `TOTAL_CRASHES` | Number of crashes represented by the record | 1–11 | 1,465,435 |
| `TOTAL_VICTIMS` | Number of victims injured or killed | 0–139 | 347,413 |

The presence of a victim count does not imply every crash in the record had a
victim. Aggregate at the level you need, and do not divide totals without checking
the denominator.

## Value sets

### Crash severity

| Value | Meaning |
|---|---|
| `CASUALTY CRASH` | A crash resulting in injury or fatality |
| `PROPERTY DAMAGE ONLY` | Material damage with no injury or fatality |

`MONDAY`, `TUESDAY`, `WEDNESDAY`, `THURSDAY`, `FRIDAY`, `SATURDAY`, `SUNDAY`.

### Months

`JANUARY`, `FEBRUARY`, `MARCH`, `APRIL`, `MAY`, `JUNE`, `JULY`, `AUGUST`,

`00:00-02:59`, `03:00-05:59`, `06:00-08:59`, `09:00-11:59`, `12:00-14:59`,

### Region values

`LOWER MAINLAND`, `SOUTHERN INTERIOR`, `VANCOUVER ISLAND`, `NORTH CENTRAL`,

`UNKNOWN` means the source had insufficient location details. The workbook also
contains narrative region definitions; see
[Tableau workbook anatomy](../explanation/tableau-workbook-anatomy.md).

The snapshot contains 11 `DERIVED_CRASH_CONFIGURATION` values:

| Value |
|---|
| `CONFLICTED` |
| `HEAD ON` |
| `MULTIPLE IMPACTS` |
| `OVERTAKING` |
| `REAR END` |
| `REAR TO REAR` |

## Nulls and missing values

The export writes every missing value as the two-character sequence `\N`
(backslash followed by `N`). It does not write empty fields; the documented
snapshot contains no empty CSV fields.

This matters when reading the data:

```python
import pandas as pd

df = pd.read_csv(
    "data/processed/icbc_reported_crashes.csv",
    keep_default_na=False,
    na_values=[r"\N"],
)
```

- `na_values=[r"\N"]` converts the sentinel to a real missing value.
- `keep_default_na=False` prevents pandas from treating ordinary codes such as
  `N` or `Y` as missing.
- Numeric nulls become floating-point `NaN` in pandas, even for integer columns.
  Cast back to a nullable integer type if needed.

The location fields are the main source of missingness:

| Field | Nulls | Share of records |
|---|---:|---:|
| `CROSS_STREET_FULL_NAME` | 815,517 | 56.1% |
| `LATITUDE` | 261,968 | 18.0% |
| `LONGITUDE` | 261,968 | 18.0% |
| `MUNICIPALITY_WITH_BOUNDARY` | 261,968 | 18.0% |
| `STREET_FULL_NAME` | 451 | 0.03% |

The equal counts for latitude, longitude, and municipality-with-boundary are
consistent with a shared geocoding limitation, but do not assume they are always
missing together in future snapshots.

### Derived `(ifnull)` fields

The export adds two convenience columns:

| Derived column | Formula | Effect in this snapshot |
|---|---|---|
| `Municipality Name (ifnull)` | `COALESCE("MUNICIPALITY_NAME", 'Unknown')` | No change: the source has no null municipalities. |
| `Street Full Name (ifnull)` | `COALESCE("STREET_FULL_NAME", 'Unknown')` | Removes 451 nulls by writing `Unknown`; existing literal `UNKNOWN` values remain uppercase. |

The derived fields make it easier to group without dropping nulls, but they hide
whether a value was originally missing. Use the physical columns when missingness
matters.

## Tableau calculated fields not in the CSV

Two Tableau fields are documented in the schema JSON but are not row-level CSV
columns:

| Field | Why it is not exported |
|---|---|
| `Metric Selector` | Aggregate whose value depends on a dashboard parameter: crash count or victim count. |
| `Crash Breakdown 2` | Dimension whose value depends on a dashboard parameter: severity, configuration, region, municipality, street, or road location. |

The schema records their choices under `parameters`. The export deliberately does
not choose one parameter value and materialize it for every row.

The `formula` strings in the schema JSON are human-readable summaries written by
the export script. They are not guaranteed to be valid Tableau syntax. The exact
Tableau formulas are in the workbook XML; see
[Tableau workbook anatomy](../explanation/tableau-workbook-anatomy.md).
